당신의 AI 에이전트는 아침 루틴, 상사의 커뮤니케이션 스타일, 절대 입 밖에 꺼내지 않는 프로젝트 코드네임, 어떤 슬랙 채널이 스트레스를 주는지까지 알고 있습니다. 이 모든 걸 기억하는 이유는 간단합니다 — **메모리가 에이전트를 유용하게 만들기 때문**입니다.

그런데 불편한 질문 하나: **이 메모리를 누가 또 읽을 수 있을까요?**

현재 답은: 서버 접근 권한이 있는 사람이면 누구든.

우리는 이 문제의 첫 번째 해결책을 만들었습니다. OpenClaw Memory Sync는 기기 간 **엔드투엔드 암호화된 메모리 동기화**를 제공합니다 — 우리조차 당신의 에이전트 메모리를 읽을 수 없습니다.

## 문제: 에이전트 메모리는 평문이다

메모리를 제공하는 모든 주요 AI 에이전트 프레임워크 — 벡터 데이터베이스, JSON 파일, 관리형 클라우드 서비스 어디든 — 메모리를 **평문으로** 저장합니다. 호스팅 서버가 내용을 읽을 수 있습니다.

이것이 의미하는 바:

- **플랫폼 운영자**가 에이전트가 축적한 당신에 대한 지식에 접근 가능
- **보안 침해** 시 인증 정보뿐 아니라 풍부한 행동 프로필까지 노출
- **기기 간 동기화** 시 암호화되지 않은 개인 데이터가 제3자 인프라를 통과
- **컴플라이언스** (GDPR, 개인정보보호법) 데이터 기밀성을 보장할 수 없으면 준수 불가

주요 에이전트 프레임워크를 전수 조사했습니다 — LangChain, CrewAI, AutoGen, Claude 메모리, ChatGPT 메모리, Mem0 등. **에이전트 메모리 E2E 암호화를 제공하는 곳은 단 하나도 없었습니다.** 일부는 저장 시 암호화(encryption at rest)를 제공하지만, 서버가 항상 키를 보유합니다. 그건 E2E가 아닙니다.

## OpenClaw Memory Sync 작동 원리

OpenClaw Memory Sync는 **제로 지식(zero-knowledge) 아키텍처**를 사용합니다: 암호화 키는 절대 기기를 떠나지 않으며, 동기화 백엔드(GitHub 프라이빗 리포지토리)는 오직 암호문만 봅니다.

### 암호화 스택

- **알고리즘**: [age](https://age-encryption.org/) (X25519) — Filippo Valsorda(전 Google Go 보안 리드)가 설계한 현대적이고 감사를 거친 암호화 도구
- **키 관리**: `sync init` 시 로컬에서 키페어 생성. 개인키는 사용자 기기에만 존재
- **백엔드**: 사용자 본인의 GitHub 프라이빗 리포지토리. 리포, 접근 권한, 삭제까지 모두 사용자가 통제

### 아키텍처

```
┌─────────────┐                    ┌─────────────┐
│   디바이스 A  │                    │   디바이스 B  │
│              │                    │              │
│  메모리       │                    │  메모리       │
│  (평문)       │                    │  (평문)       │
│      │       │                    │      ▲       │
│      ▼       │                    │      │       │
│  age 암호화   │                    │  age 복호화   │
│      │       │                    │      ▲       │
└──────┼───────┘                    └──────┼───────┘
       │                                   │
       ▼                                   │
  ┌─────────────────────────────────────────┐
  │      GitHub 프라이빗 리포지토리           │
  │        (암호화된 블롭만 저장)              │
  └─────────────────────────────────────────┘
```

**GitHub가 보는 것**: 암호화된 바이너리 블롭. 파일명이 내용을 드러내지 않습니다. 메타데이터 누출 없음.

**사용자 기기가 보는 것**: 로컬에서 복호화된 전체 에이전트 메모리.

## 빠른 데모

### Memory Sync 초기화

```bash
openclaw sync init
```

age 키페어를 생성하고 GitHub 리포지토리에 연결합니다. 개인키는 로컬 키체인에 저장되며 — 절대 기기를 떠나지 않습니다.

### 메모리를 클라우드에 푸시

```bash
openclaw sync push
```

메모리 파일이 age 공개키로 로컬에서 암호화된 후, 프라이빗 GitHub 리포에 암호화된 블롭으로 푸시됩니다.

### 다른 기기에서 메모리 풀

```bash
openclaw sync pull
```

새 기기에서 개인키를 전달한 후(QR 코드 또는 보안 복사), `sync pull`이 암호화된 블롭을 가져와 로컬에서 복호화합니다.

이게 전부입니다. 세 개의 명령어. 완전한 E2E 암호화.

## 왜 지금 이것이 중요한가

AI 에이전트가 "유용한 장난감"에서 "없으면 안 되는 비서"로 진화하고 있습니다. 그 과정에서 점점 더 민감한 데이터를 축적합니다:

- **개인 패턴**: 수면 스케줄, 감정 상태, 인간관계 역학
- **업무 인텔리전스**: 프로젝트 전략, 조직도 정치, 연봉 협상 내용
- **접근 맥락**: 어떤 시스템을 쓰는지, 인증 방식, 워크플로우 단축키

이 데이터는 **브라우징 히스토리보다 더 민감할 수 있습니다**. 브라우저는 당신이 뭘 검색했는지 알지만, 에이전트는 당신이 *무슨 생각을 했는지* 압니다.

에이전트가 멀티 디바이스(폰, 노트북, 홈서버)로 확장되면서 메모리 동기화는 필수가 됩니다. 그리고 암호화 없는 동기화는 보안 부채입니다.

기존 솔루션을 찾아봤습니다. 없었습니다. 그래서 만들었습니다.

## 제로 지식 보장

"제로 지식"이 정확히 무엇을 의미하는지 명확히 하겠습니다:

1. **OpenClaw 서버**는 메모리도, 암호화 키도 절대 보지 못합니다
2. **GitHub**는 암호화된 블롭만 저장합니다 — 리포가 공개되더라도 데이터는 읽을 수 없습니다
3. **키 위탁(key escrow) 없음** — 개인키를 잃으면 암호화된 메모리는 복구 불가능합니다. 이것은 버그가 아니라 기능입니다.

이것은 Signal이 메시지에, 1Password가 인증 정보에 적용하는 것과 동일한 보안 모델입니다. 우리는 이를 에이전트 메모리에 적용합니다.
