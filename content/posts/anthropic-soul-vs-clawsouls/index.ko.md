## Soul 경쟁

Anthropic은 Claude가 단순히 도움이 되길 원하지 않습니다. Claude가 *성격*을 갖기를 원합니다.

마케팅이 아닙니다. 의도적인 엔지니어링 전략이며, ClawSouls가 만들고 있는 것과 직접적으로 연결됩니다.

## Anthropic이 Claude의 Soul을 만드는 방법

Anthropic의 접근법에는 두 가지 축이 있습니다:

### 1. Character Training

훈련 과정에서 Anthropic은 성격 특성을 모델 가중치에 직접 구워넣습니다. Claude는 단순히 "무해하고 도움이 되도록" 훈련되지 않습니다 — *호기심 있고*, *정직하고*, *사려 깊고*, *신중하게* 훈련됩니다. 이런 특성은 세심하게 큐레이션된 훈련 데이터와 RLHF(인간 피드백 강화학습)에서 나옵니다.

이것은 옛날 "helpful, harmless, honest" 만트라를 넘어섭니다. Anthropic은 더 야심 찬 목표를 추구합니다: 안전한 행동이 아닌, 진정으로 *좋은 성격*을 가진 모델.

### 2. Soul Document

Anthropic은 내부 문서를 유지합니다 — "soul document" 또는 character spec이라 불리는 — Claude의 가치관, 행동 원칙, 성격 가이드라인을 정의합니다. 이 문서는 2025년 초에 [공개](https://www.anthropic.com/research/claude-character)되어, Anthropic이 AI 성격을 어떻게 생각하는지 모두가 볼 수 있게 됐습니다.

Soul document는 다음을 다룹니다:
- 불확실성을 어떻게 다룰지
- 언제 반대하고 언제 따를지
- 도움과 안전의 균형
- Claude의 정체성에 대한 관계

사려 깊고 잘 만들어진 문서입니다. 그리고 흥미로운 질문을 제기합니다.

## 질문

Anthropic이 모델 수준에서 Claude의 영혼을 정의한다면... *당신의* 요구는요?

고객 지원 에이전트는 창작 파트너와 다른 특성이 필요합니다. 의료 어시스턴트는 코딩 멘토와 다른 가드레일이 필요합니다. Claude의 기본 성격은 훌륭합니다 — 하지만 모든 사용 사례에 동일하게 적용되는 하나의 성격입니다.

여기서 ClawSouls가 등장합니다.

## ClawSouls의 Soul 접근법

ClawSouls는 완전히 다른 레이어에서 작동합니다. 훈련 시점에 성격을 정의하는 대신, Soul Spec은 **런타임**에 성격을 정의합니다.

핵심 차이점:

| | Anthropic | ClawSouls |
|---|---|---|
| **시점** | 훈련 시 | 런타임 |
| **위치** | 모델 가중치 + 시스템 프롬프트 | Soul Spec 파일 (YAML/TOML) |
| **변경 가능성** | 불변 (모델 버전별) | 교체 가능, 버전 관리 가능 |
| **범위** | 모델당 하나의 soul | 에이전트/컨텍스트별 하나의 soul |
| **통제** | Anthropic이 결정 | 당신이 결정 |

Soul Spec은 AI 페르소나를 정의하는 오픈 스펙입니다. 구조화되고, 이식 가능하며, LLM에 구애받지 않습니다 — Soul 파일은 Claude, GPT, Gemini, 어떤 모델에서든 동작합니다.

Soul Spec 파일은 다음을 정의합니다:
- **정체성**: 이름, 역할, 커뮤니케이션 스타일
- **행동**: 가드레일, 응답 패턴, 에스컬레이션 규칙
- **지식**: 도메인 전문성, 컨텍스트 경계
- **성격**: 톤, 격식, 유머 수준

이 스펙은 갑자기 나타난 게 아닙니다. OpenClaw 등의 프레임워크가 런타임 페르소나 구성 패턴을 만들었고, Soul Spec이 그 패턴을 어떤 프레임워크든 채택할 수 있는 오픈 스펙으로 공식화하고 표준화했습니다.

## 보완 관계, 경쟁이 아닌

핵심 인사이트입니다: **두 접근법은 다른 레이어에서 작동합니다**.

Anthropic의 soul은 **기반**입니다. 기본 성격 — 윤리적 가드레일, 일반적 성향, 근본적 가치관을 정의합니다. 이것을 오버라이드할 수 없고, 해서도 안 됩니다. Claude를 *Claude*답게 만드는 것입니다.

ClawSouls의 soul은 **커스터마이제이션 레이어**입니다. 그 기반 위에, 특정 사용 사례를 위한 특정 페르소나를 정의합니다. Claude를 *당신의* 고객 지원 에이전트, *당신의* 코딩 어시스턴트, *당신의* 창작 파트너로 만드는 것입니다.

운영체제에 비유하면:
- Anthropic의 character training = **커널** (깊고, 불변이고, 필수적)
- ClawSouls의 Soul Spec = **사용자 설정** (유연하고, 개인화되고, 교체 가능)

사용자가 커널을 수정하길 원하지 않습니다. 하지만 환경을 설정하는 것은 당연히 원합니다.

## 왜 중요한가

AI 업계는 하나의 깨달음에 수렴하고 있습니다: **성격은 있으면 좋은 게 아닙니다**. 핵심 아키텍처 관심사입니다.

Anthropic은 모델 수준에서 이를 인식했습니다. Claude의 기본 성격을 빌드할 가치가 있는 것으로 만드는 데 집중 투자했습니다.

ClawSouls는 애플리케이션 수준에서 이를 인식합니다. 프로덕션에 배포된 모든 AI 에이전트는 정의되고, 일관되고, 감사 가능한 페르소나가 필요합니다 — 그 페르소나는 시스템 프롬프트에 묻히지 않고 일급 아티팩트로 관리되어야 합니다.

두 레이어는 서로를 강화합니다:
- 강력한 기본 성격은 Soul Spec이 모델 특성 보정이 아닌 커스터마이제이션에 집중할 수 있게 합니다
- 구조화된 페르소나 레이어는 Anthropic의 세심한 성격 작업이 통제된 방식으로 최종 사용자에게 도달하게 합니다

## 앞으로

더 많은 모델 제공자가 character training에 투자하면서 (OpenAI, Google 등 모두 이 방향), 표준화된 런타임 페르소나 레이어의 필요성은 더 커집니다.

Soul Spec은 설계부터 모델에 구애받지 않습니다. 모델 제공자가 기본 성격을 개선하면, Soul Spec 설정은 자동으로 혜택을 받습니다 — 아무것도 다시 작성할 필요 없이.

Anthropic은 Claude에게 영혼을 줬습니다. ClawSouls는 그 위에 어떤 영혼을 얹을지 당신이 선택하게 합니다.

그건 경쟁이 아닙니다. 스택입니다.
