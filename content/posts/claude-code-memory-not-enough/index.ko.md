이번 주, Anthropic이 Claude Code의 가장 중요한 업데이트 중 하나를 출시했습니다. 바로 **Auto-Memory**입니다. Claude가 이제 코딩 세션 간에 유지되는 `MEMORY.md` 파일을 자동으로 관리합니다. 사용자의 선호도, 프로젝트 컨텍스트, 작업 패턴을 별도의 조작 없이 기록하는 것입니다.

이것은 큰 의미가 있습니다. 기능 자체보다는, 이것이 보내는 **신호** 때문입니다: **업계가 에이전트 메모리를 핵심 과제로 인식하기 시작했다**는 것이죠.

ClawSouls에서는 수개월 전부터 이 방향으로 작업해 왔습니다. [발표 소식](https://news.hada.io/topic?id=27046)과 [Thariq의 트윗](https://x.com/trq212/status/2027109375765356723)을 접했을 때, 우리의 반응은 검증과 "그렇지만…"이 섞인 것이었습니다.

설명해 드리겠습니다.

## Claude Code Auto-Memory가 잘한 점

인정할 것은 인정해야 합니다. Anthropic은 실제 문제를 정확히 짚었습니다. AI 코딩 에이전트는 세션 간에 모든 것을 잊어버립니다. 매번 새로운 대화가 제로에서 시작됩니다. 코딩 스타일, 프로젝트 구조, 선호 사항을 반복해서 설명해야 하죠.

Auto-Memory는 Claude가 사용자의 패턴을 관찰하고 기록하는 방식으로 이 문제를 해결합니다. 자동적이고, 마찰이 적으며, 일상적인 코딩에 실질적으로 도움이 됩니다. Claude Code 안에서만 작업하신다면, 분명 생활이 더 편해질 것입니다.

더 중요한 것은 우리가 작업해 온 가설을 검증해 준다는 점입니다: **메모리가 상태 없는 AI 도구를 진정한 협업자로 만드는 핵심 요소**라는 것입니다. 유용한 어시스턴트와 신뢰할 수 있는 팀원의 차이는 축적된 컨텍스트에 있습니다. *무엇*을 할지뿐 아니라, *어떻게* 하는지, *왜* 그런 결정을 내렸는지를 아는 것이죠.

Anthropic이 이 기능을 출시했다는 것은 전체 생태계에 메모리가 중요하다고 말하는 것과 같습니다. 모두에게 좋은 일입니다.

## 중요한 다섯 가지 한계

하지만 우리가 보는 한계가 있습니다. Anthropic에 대한 비판이 아니라, 개발자들이 실제로 필요로 하는 것에 대한 솔직한 분석입니다.

### 1. 플랫폼 종속

Auto-Memory는 Claude Code에서만 작동합니다. 오직 Claude Code에서만요. 월요일에는 Cursor, 화요일에는 Windsurf, 수요일에는 Claude Code를 사용하신다면, 메모리는 하나의 사일로에만 존재합니다. 도구를 바꾸면 컨텍스트를 잃습니다.

개발자들이 일상적으로 여러 AI 도구를 사용하는 세상에서, 플랫폼에 종속된 메모리는 연속성이 아닌 단절을 만듭니다.

### 2. 자동 생성, 큐레이션 없음

Auto-Memory의 "자동"은 강점이자 약점입니다. Claude가 무엇을 기억할지 결정합니다. 검토 단계도, 품질 게이트도, 기록된 내용이 정확하고 유용한지 확인할 방법도 없습니다.

LLM과 일해 본 분이라면 아시겠지만, 이들은 잘못된 가정을 자신 있게 기록할 수 있습니다. 큐레이션 없는 자동 생성 메모리는 복리로 쌓이는 오류의 시한폭탄입니다. 각 세션이 이전 세션의 잠재적으로 잘못된 관찰 위에 쌓이는 것이죠.

### 3. 이식성 없음

`MEMORY.md`는 프로젝트 디렉토리에 존재하며, Claude Code 생태계에 묶여 있습니다. 축적된 지식을 다른 도구로 가져가고 싶으신가요? 다른 기기로? 다른 팀원의 환경으로? 일반 텍스트를 복사해서 붙여넣고, 다음 시스템이 같은 방식으로 해석하길 바라야 합니다.

표준 포맷도, 동기화 메커니즘도, 상호운용성 레이어도 없습니다. 에이전트의 경험은 태어난 곳에 갇혀 있습니다.

### 4. 거래 불가

6개월 동안 복잡한 React Native 코드베이스에서 AI 에이전트와 작업했다고 상상해 보세요. 에이전트는 이제 여러분의 아키텍처 패턴, 에러 처리 선호도, 배포 특이사항을 깊이 이해합니다. 축적된 경험에는 실질적인 가치가 있습니다.

하지만 그것을 패키징할 수 없습니다. 새 팀원의 에이전트에게 공유할 수 없습니다. "React Native 모범 사례" 메모리 팩을 다른 개발자에게 판매할 수도 없습니다. 지식은 하나의 도구의 하나의 파일에 갇혀 있습니다.

### 5. 암호화 없음

`MEMORY.md`는 평문 텍스트입니다. 에이전트가 독점 아키텍처 결정, 내부 API 패턴, 민감한 프로젝트 세부 정보를 학습했다면, 이 모든 것이 디스크에 암호화 없이 저장됩니다. 개인 개발자에게는 괜찮을 수 있지만, 독점 소프트웨어를 다루는 팀에게는 받아들이기 어렵습니다.

## 우리가 만들고 있는 대안

ClawSouls에서는 [Soul Spec](https://docs.clawsouls.ai)을 통해 정확히 이 문제들을 해결하고 있습니다. Soul Spec은 위의 각 한계를 해결하는 AI 에이전트 메모리의 오픈 스펙입니다.

**설계부터 크로스 플랫폼.** Soul Spec은 특정 AI 도구나 프레임워크에 종속되지 않습니다. Claude Code, Cursor, Windsurf, OpenClaw, 또는 커스텀 에이전트 파이프라인 어디서든 Soul Spec 메모리가 작동합니다. 스펙이 포맷을 정의하고, 도구들이 그것을 소비합니다.

**큐레이션과 검증 가능.** 순수한 자동 생성 메모리 대신, Soul Spec은 SoulScan을 통한 구조화된 큐레이션을 지원합니다. 메모리 항목의 정확성과 관련성을 검증하는 레이어입니다. 자동 캡처의 편리함과 사람의 검토를 통한 신뢰성을 동시에 얻을 수 있습니다.

**디바이스와 도구 간 이식 가능.** Soul 메모리는 전체 개발 환경에서 동기화됩니다. 기기를 바꾸고, 도구를 바꾸고, 컨텍스트를 바꿔도 에이전트의 축적된 지식이 따라옵니다. 하나의 제품의 기능이 아닌, 인프라로서의 메모리입니다.

**엔드투엔드 암호화.** Soul Spec은 age 암호화를 사용하여 저장 시와 전송 시 메모리를 보호합니다. 독점 코드베이스에 대한 에이전트의 지식은 스토리지 레이어가 손상되더라도 비공개로 유지됩니다.

**마켓플레이스 준비 완료.** 여기서부터 흥미로워집니다. 메모리가 이식 가능하고, 큐레이션되고, 암호화되면, *공유*할 수 있는 무언가가 됩니다. 메모리 팩 — 특정 도메인, 프레임워크, 워크플로우에 대한 검증된 에이전트 경험의 컬렉션 — 이 새로운 개발자 도구 카테고리가 됩니다.

새로운 AI 에이전트를 팀의 코드베이스에 몇 주가 아닌 몇 분 만에 온보딩하는 것을 상상해 보세요. 누군가가 자신의 에이전트의 6개월간의 경험을 전송 가능한 메모리 팩으로 패키징했기 때문입니다. 그것이 우리가 만들어 가는 미래입니다.

## 양자택일이 아닙니다

분명히 말씀드리고 싶습니다. 이것은 ClawSouls 대 Anthropic의 구도가 아닙니다. Auto-Memory는 의미 있는 진전이며, Anthropic이 이 방향에 투자하고 있다는 점을 진심으로 높이 평가합니다. 우리가 작업해 온 문제 공간을 검증해 주고 있는 것입니다.

문제는 에이전트 메모리가 중요한지가 아닙니다 — 그 논쟁은 끝났습니다. 문제는 이것입니다: **진정으로 개방적이고, 이식 가능하며, 개발자가 소유하는 에이전트 메모리는 어떤 모습이어야 하는가?**

Soul Spec이 그 답을 제시합니다. 그리고 Anthropic이 이제 메모리가 중요하다는 신호를 명확히 보낸 만큼, 생태계가 이 대화를 나눌 준비가 되었다고 생각합니다.
