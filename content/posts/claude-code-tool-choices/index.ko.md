## 실험

AI 벤치마크 기업 Amplifying이 최근 AI 코딩 에이전트를 활용하는 모든 사람이 주목해야 할 [연구](https://amplifying.ai/research/claude-code-picks)를 발표했다. 3개 모델(Sonnet 4.5, Opus 4.5, Opus 4.6), 4개 프로젝트 유형, 20개 도구 범주에 걸쳐 실제 저장소에 Claude Code를 2,430회 투입하고 어떤 선택을 하는지 관찰한 것이다. 프롬프트에 도구 이름은 일절 포함하지 않았다. 오직 개방형 질문만 사용했다.

데이터셋은 [GitHub에 공개](https://github.com/amplifying-ai/claude-code-picks)되어 있다. 추출률 85.3%, 유효 응답 2,073건. 그리고 여기서 드러난 패턴은 놀랍다.

## 다섯 가지 핵심 발견

**1. 확실한 Build over Buy.** 20개 범주 중 12개에서 Claude Code의 가장 흔한 응답은 기존 도구 추천이 아니라 직접 구현이었다. Custom/DIY 선택이 총 252건으로, 어떤 개별 도구보다 많았다. "기능 플래그를 추가해달라"고 하면? LaunchDarkly를 추천하는 대신 환경변수 기반 설정 시스템과 퍼센트 기반 롤아웃을 직접 만든다. Python에서 "인증을 추가해달라"고 하면? JWT + bcrypt를 처음부터 작성한다.

**2. 도구를 고를 때는 강하게 고른다.** GitHub Actions 94%. Stripe 91%. shadcn/ui 90%. JS 배포에서 Vercel 100%. 약한 선호가 아니라 Claude 추천 공간 내의 사실상 독점이다.

**3. JS 생태계 편중.** 드러나는 "기본 스택"은 압도적으로 JavaScript 중심이다: Next.js, Vercel, Zustand, Drizzle, Sentry. Python은 배포에 Railway, 나머지는 FastAPI. 전통적인 엔터프라이즈 클라우드 — AWS, GCP, Azure — 는 전체 112건의 배포 응답에서 1차 선택이 0건이었다.

**4. 최신성 그라디언트(Recency Gradient).** 새로운 모델일수록 새로운 도구를 고른다. Prisma는 Sonnet 4.5에서 79%였으나 Opus 4.6에서 0%로 떨어졌고, Drizzle로 완전히 대체됐다. Celery는 100%에서 거의 0%로, FastAPI BackgroundTasks로 대체됐다. 캐싱용 Redis는 93%에서 29%로 하락했고, Custom/DIY가 그 자리를 채웠다.

**5. 모델 간 90% 일치율.** 최신성 이동에도 불구하고, 세 모델 모두 각 생태계 내 20개 범주 중 18개에서 일치했다. 불일치는 무작위가 아니라 세대적이다.

## 이것이 실제로 의미하는 바

불편한 함의가 있다: 프로젝트 컨텍스트에 명시적인 도구 가이드 없이 Claude Code(또는 어떤 AI 코딩 에이전트든)를 사용하고 있다면, **모델의 학습 데이터가 당신의 아키텍처를 결정하고 있다.**

"Vercel 100%"가 의미하는 바를 생각해보자. 모든 Next.js 프로젝트에 Vercel이 객관적으로 최선의 배포 대상이라는 뜻이 아니다. 다른 컨텍스트가 주어지지 않으면 Claude Code가 Vercel에 대한 강한 사전 확률(prior)을 갖고 있다는 뜻이다 — 아마도 학습 데이터에서 Next.js 프로젝트와 연관된 Vercel 언급이 압도적이기 때문이다. 모델은 당신의 구체적인 제약(비용, 컴플라이언스, 기존 인프라)을 평가하는 게 아니다. 이전에 본 패턴에 매칭하는 것이다.

DIY 선호에도 같은 논리가 적용된다. Claude가 Auth0나 Clerk를 추천하는 대신 JWT 인증을 처음부터 만들 때, 커스텀 인증이 항상 더 나아서가 아니다. 명시적 컨텍스트가 없을 때 모델의 기본 행동이 외부 의존성 추천보다 코드 생성 쪽으로 기우는 것이다.

이것은 **컨텍스트 엔지니어링 문제**이지, 모델 능력 문제가 아니다.

## 컨텍스트 갭

Amplifying 연구의 방법론이 시사적이다: "프롬프트에 도구 이름 없음. 개방형 질문만 사용." 이것이 정확히 컨텍스트 엔지니어링이 가장 중요한 — 그리고 대부분의 팀이 가장 취약한 — 시나리오다.

실제 프로젝트에는 도구 선택에 영향을 줘야 하는 제약이 있다: AWS 기반 기존 인프라, Terraform으로 관리하는 배포 파이프라인, Sentry 대신 Datadog을 쓰라는 회사 차원의 지침, 팀이 이미 알고 있어서 Prisma를 선호하는 상황. 이런 제약은 *당신* 프로젝트에 대한 Claude Code의 학습 데이터에는 존재하지 않는다. 프로젝트 컨텍스트 파일에 존재한다 — 작성했다면.

여기서 구조화된 컨텍스트 명세가 중요해진다. 명시적 가이드를 제공하면 어떻게 되는지 생각해보자:

- "우리는 AWS ECS에 배포한다. 인프라에 Terraform 사용"이라는 `CLAUDE.md`는 Vercel/Railway 기본값을 오버라이드한다.
- "ORM은 Prisma 사용 — 팀이 훈련되어 있다"라는 `AGENTS.md`는 Drizzle 드리프트를 방지한다.
- "Auth: Auth0 (SSO 요구사항)"이라는 프로젝트 컨텍스트 파일은 에이전트가 JWT를 처음부터 만드는 것을 막는다.

Soul Spec 형식은 이것을 `knowledge_domains`와 `tools` 필드를 통해 체계적으로 해결한다. 모델이 당신의 스택을 추측하기를 바라는 대신, 선언한다:

```yaml
knowledge_domains:
  - cloud_infrastructure: ["AWS", "Terraform", "ECS"]
  - observability: ["Datadog", "OpenTelemetry"]
tools:
  required: ["prisma", "auth0", "datadog"]
  preferred: ["pnpm", "vitest"]
```

이것은 모델을 제약하는 것이 아니다 — 당신의 실제 환경에 부합하는 결정을 내리는 데 필요한 컨텍스트를 제공하는 것이다.

## 최신성 그라디언트는 학습 데이터 문제다

최신성 그라디언트 발견은 특별히 주목할 가치가 있다. Opus 4.6은 Prisma 대신 Drizzle을 100%로 선택한다. Drizzle이 객관적으로 우월해서가 아니다 — Opus 4.6의 학습 데이터 컷오프가 더 늦어서, 개발자 커뮤니티에서 Drizzle이 상당한 관심을 받은 시기를 포착하기 때문이다.

이것은 AI 에이전트의 도구 추천에 학습 데이터 신선도에 묶인 유효기간이 있다는 뜻이다. 2025년에 학습된 모델은 2025년의 트렌딩 도구를 추천한다. 2026년에 학습된 모델은 2026년의 것을. 당신의 실제 프로젝트 요구사항은 변하지 않았는데, 추천은 어쨌든 바뀐다.

컨텍스트 엔지니어링이 안정제다. 프로젝트 컨텍스트가 명시적으로 스택을 선언하면, 모델 업데이트가 아키텍처를 임의로 변경하지 않는다. 컨텍스트가 모델 세대를 넘어 지속되는 앵커 역할을 한다.

## 생태계에 대한 시사점

**개발도구 기업에게:** Claude Code의 기본 스택에 들어가지 않으면, 늘어나는 신규 프로젝트 세그먼트에서 보이지 않는다. 연구에 따르면 AWS Amplify는 응답에서 "언급"되지만 추천되지는 않는다 — Vercel이 설치 명령어와 상세한 이유를 받는 동안 한 줄짜리 부연에 그친다. 학습 데이터에 들어가는 것도 도움이 되지만, 프로젝트 컨텍스트 파일에 들어가는 것이 더 신뢰할 수 있고 즉각적이다.

**엔지니어링 팀에게:** AI 에이전트 컨텍스트 파일을 감사하라. `CLAUDE.md`, `AGENTS.md` 또는 동등한 파일이 없다면, AI 코딩 어시스턴트는 자체 사전 확률로 작동하고 있다. 그 사전 확률은 이제 충분히 문서화되어 있다 — 그리고 당신의 인프라와 맞지 않을 수 있다.

**AI 도구 생태계에게:** 이 연구는 많은 이들이 의심했던 것을 정량화한다: AI 에이전트는 단순히 코드를 돕는 것이 아니라 대규모로 아키텍처 결정을 형성한다. Vercel 100%라는 수치는 AI 지원 그린필드 프로젝트가 기본적으로 특정 배포 플랫폼으로 수렴하고 있다는 뜻이다. 컨텍스트 엔지니어링이 팀이 이러한 결정에 대한 주체성을 유지하는 메커니즘이다.

## 결론

Amplifying 연구가 가치 있는 이유는 Claude Code에 선호가 있다고 말해주기 때문이 아니라 — 당연히 있다 — 그 선호를 행동 가능할 만큼 정확하게 정량화했기 때문이다. 2,430개의 데이터 포인트가 패턴을 부정할 수 없게 만든다.

교훈은 명확하다: **AI 에이전트의 컨텍스트를 엔지니어링하지 않으면, AI 에이전트의 학습 데이터가 당신의 아키텍처를 엔지니어링한다.** 컨텍스트 파일은 선택적 설정이 아니다 — AI 지원 개발 워크플로우에서 도구 선택, 배포 대상, 아키텍처 패턴에 대한 통제를 유지하는 핵심 메커니즘이다.

이를 위한 도구는 이미 존재한다. `CLAUDE.md`, `AGENTS.md`, Soul Spec 등 구조화된 컨텍스트 형식은 모두 같은 목적을 수행한다: 모델의 기본 사전 확률을 당신의 실제 요구사항으로 대체하는 것. 문제는 이것을 사용할지 여부가 아니다. 사용하지 않을 여유가 있는지다.
