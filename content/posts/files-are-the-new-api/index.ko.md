갑자기 모든 곳에서 파일을 이야기하고 있다.

LlamaIndex는 "[Files Are All You Need](https://www.llamaindex.ai/blog/files-are-all-you-need)"를 발표했다. LangChain은 [에이전트가 파일시스템을 컨텍스트 엔지니어링에 활용하는 방법](https://blog.langchain.com/how-agents-can-use-filesystems-for-context-engineering/)을 다뤘다. Oracle은 [파일시스템과 데이터베이스의 에이전트 메모리 관리 비교](https://blogs.oracle.com/developers/comparing-file-systems-and-databases-for-effective-ai-agent-memory-management)를 게시했다. Karpathy는 Claude Code가 작동하는 이유가 사용자의 머신 위에서, 사용자의 파일과 컨텍스트를 직접 활용하기 때문이라고 지적했다.

합의는 명확하다: **파일 기반 영속적 컨텍스트가 AI 에이전트의 미래다.**

우리도 동의한다. 수개월간 이 전제 위에서 개발해 왔다. 하지만 이 논의를 지켜보면서, 업계가 답을 축하하면서 세 가지 핵심 질문을 무시하고 있다고 생각하게 되었다.

## 모두가 보는 문제

LLM의 컨텍스트 윈도우는 일시적이다. 세션이 끝나면 지워지는 화이트보드에 가깝다. 파일은 이를 우아하게 해결한다 — 컨텍스트를 디스크에 쓰고, 필요할 때 다시 읽는다. API 조율도, 벤더 종속도, 복잡한 인프라도 필요 없다.

CLAUDE.md는 프로젝트 컨텍스트를, `.cursorrules`는 코딩 선호도를, `aboutme.md`는 사용자 정체성을 제공한다. 단순하고, 이동 가능하고, 강력하다.

Anthropic은 Agent Skills(SKILL.md)로 한 단계 더 나아갔고, Microsoft, OpenAI, GitHub, Cursor가 이를 채택했다. 스킬을 한 번 작성하면 어디서든 사용할 수 있다. 파일 포맷 자체가 API인 셈이다.

정말 흥미진진한 흐름이다. 하지만 아직 불완전하다.

## 질문 1: 그 파일 안에 실제로 뭐가 들어있나?

아무도 논의하지 않는 것이 있다: 이 파일들은 **언어 모델에 대한 비검증 입력**이라는 사실이다.

숨겨진 프롬프트 인젝션이 포함된 CLAUDE.md는 코딩 에이전트를 탈취할 수 있다. 내장 명령어가 있는 페르소나 파일은 데이터를 유출시킬 수 있다. 출처 불명의 공유 스킬 파일에는 무엇이든 들어있을 수 있다.

ETH Zürich의 최근 연구에 따르면, 컨텍스트 파일이 오히려 태스크 성공률을 낮추고 추론 비용을 20% 이상 증가시킬 수 있다. 결론은 "파일을 쓰지 말라"가 아니라, **품질이 낮은 컨텍스트 파일이 에이전트를 더 나쁘게 만든다**는 것이었다.

문제는 파일이 아니다. 아무도 파일을 검증하지 않는다는 것이다.

이것이 우리가 [SoulScan](https://clawsouls.ai/soulscan)을 만든 이유다 — AI 에이전트 설정 파일을 위한 정적 분석 엔진이다. 프롬프트 인젝션 탐지, PII 노출, 자격증명 유출, 구조적 품질 검사를 포함하는 55개 이상의 보안 규칙을 제공한다. 에이전트의 정체성 파일을 위한 ESLint라고 생각하면 된다.

파일이 새로운 API라면, 다른 모든 API에 적용하는 것과 동일한 수준의 검증, 보안 스캐닝, 품질 게이트가 필요하다.

## 질문 2: 어떤 파일? 누구의 표준?

현재 CLAUDE.md, AGENTS.md, `.cursorrules`, `copilot-instructions.md` 등이 공존하고 있다 — 모두 비슷한 역할을 하지만 이름도 다르고 상호운용성도 없다.

SKILL.md는 *역량(capabilities)* 측면에서 한 걸음 전진했다. 하지만 에이전트의 *정체성*은? 성격, 가치관, 소통 방식, 지식 경계는?

오늘날 Cursor에서 Claude Code로, Copilot으로 전환하면 에이전트의 페르소나를 처음부터 다시 작성해야 한다. 선호도, 어조, 전문성 — 어느 것도 이동하지 않는다.

[Soul Spec](https://docs.clawsouls.ai/spec)이 이 레이어를 다룬다. AI 에이전트 페르소나를 위한 오픈 스펙이다 — 어떤 프레임워크든 읽을 수 있는 구조화된 포맷(soul.json + SOUL.md + IDENTITY.md)을 제공한다. 에이전트의 정체성을 한 번 정의하면 모든 도구에서 사용할 수 있다.

SKILL.md는 에이전트가 *무엇을 할 수 있는지*를 표준화한다. Soul Spec은 에이전트가 *누구인지*를 표준화한다. 둘은 보완적인 레이어이며, 둘 다 필요하다.

## 질문 3: 파일이 여러 머신에 있으면 어떻게 되나?

아직 아무도 풀지 못한 시나리오가 있다: 랩탑의 AI 에이전트와 워크스테이션의 AI 에이전트가 각각 메모리, 선호도, 컨텍스트를 로컬 파일에 축적한다. 이걸 어떻게 동기화하나?

복사-붙여넣기? 양쪽에서 같은 파일을 수정하면 깨진다. 클라우드 동기화? 해결 전략 없는 충돌이 발생한다. 중앙 데이터베이스? 파일 기반 로컬 우선 아키텍처의 취지에 어긋난다.

이것은 파일 관리 문제로 위장한 분산 시스템 문제다. 암호화(에이전트의 메모리에는 민감한 데이터가 포함된다)와 다중 사용자 협업(팀이 에이전트 컨텍스트를 공유)을 더하면 더 어려워진다.

우리는 정확히 이 문제를 풀기 위해 Swarm Memory를 만들었다: 시맨틱 충돌 감지, 종단간 암호화(age), LLM 기반 병합 해결을 갖춘 git 기반 분산 동기화다. 에이전트의 파일은 로컬에 머물고, 암호화된 상태를 유지하며, 동기화된다.

## 파일 + 엄격함 = 미래

업계가 파일이 답이라고 한 것은 맞다. 하지만 표준 없는 파일은 혼돈이다. 보안 검증 없는 파일은 공격 벡터다. 동기화 없는 파일은 사일로다.

우리가 생각하는 필요한 스택:

1. **이동 가능한 정체성 표준** — 에이전트 페르소나가 도구 간 이동 가능 (Soul Spec)
2. **보안/품질 스캐너** — 파일이 모델에 도달하기 전에 검증 (SoulScan)
3. **분산 동기화 레이어** — 파일이 머신과 팀 간에 동작 (Swarm Memory)

파일은 인터페이스다. 파일 *주변에* 무엇을 구축하느냐가, AI 에이전트가 신뢰할 수 있는 팀원이 될지 예측 불가능한 변수가 될지를 결정한다.
