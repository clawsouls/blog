## AI 페르소나 프로젝트의 짧은 역사

AI 에이전트에게 고유한 성격을 부여하려는 시도는 새로운 것이 아닙니다. 여러 프로젝트가 시도했습니다. 대부분 죽었습니다.

### OpenSouls (⭐294) — 서비스 종료

"디지털 존재의 마음을 위한 NextJS + Vercel"을 자처했습니다. TypeScript 런타임을 만들었습니다:

- **WorkingMemory**: 에이전트 메모리의 불변 컬렉션
- **cognitiveSteps**: 메모리 상태를 변환하는 함수
- **MentalProcesses**: 행동을 위한 상태 머신 (행복 → 좌절 → 호기심)

현재: 웹사이트 다운, 문서 사라짐, 저장소 삭제, npm 1년 이상 침묵.

### SocialAGI — 서비스 종료

OpenSouls의 전신. LLM에 "사회적 지능"을 추가하는 JavaScript 라이브러리. Soul Engine에 흡수되었고, 둘 다 함께 죽었습니다.

### arifOS (⭐29) — 활성, 다른 레이어

13개 거버넌스 층과 8계층 스택을 가진 Python "Constitutional AI Kernel". 흥미로운 프로젝트지만 AI 안전/거버넌스를 대상으로 하며, 페르소나 디자인이 아닙니다. 경쟁자가 아닌 잠재적 보완재.

## 패턴

죽은 모든 프로젝트에 공통점이 있습니다: **런타임 의존성**.

OpenSouls는 Bun + 자체 SDK를 요구했습니다. SocialAGI는 자체 npm 패키지를 요구했습니다. 둘 다 AI에 성격을 부여하기 위해 전체 도구 체인을 채택하도록 강제했습니다.

생태계가 전환되자(Character.AI 열풍 → 에이전트/도구 시대), 이 경직된 런타임은 적응할 수 없었습니다.

## 왜 스펙은 살아남는가

기술 분야의 생존자를 보세요:

| 스펙/포맷 | 수명 | 런타임 필요? |
|---|---|---|
| JSON | 20년+ | 아니오 |
| Markdown | 20년+ | 아니오 |
| HTML | 30년+ | 아니오 (여러 엔진이 해석) |
| Docker (OCI 스펙) | 10년+ | 여러 런타임 |

죽은 것들:

| 기술 | 수명 | 사인 |
|---|---|---|
| Flash | ~15년 | 런타임 의존성 |
| Silverlight | ~5년 | 런타임 의존성 |
| Java Applets | ~10년 | 런타임 의존성 |

**패턴은 명확합니다**: 포맷과 스펙은 그것을 위해 만들어진 런타임보다 오래 삽니다.

## Soul Spec의 선택

Soul Spec은 런타임이 아니라 파일 포맷입니다. 에이전트의 성격은 어떤 프레임워크든 읽을 수 있는 마크다운 파일로 정의됩니다.

설치할 SDK 없음. 실행할 서버 없음. 의존할 벤더 없음.

OpenClaw이 내일 사라져도 Soul Spec 파일은 여전히 동작합니다. *우리*가 내일 사라져도 스펙은 공개되어 있고 파일은 당신의 디스크에 있습니다.

이건 가정이 아닙니다. OpenSouls 사용자는 플랫폼이 사라졌을 때 모든 것을 잃었습니다.

## 트레이드오프

선언적 스펙은 런타임 엔진보다 기능이 적습니다. OpenSouls는 감정 상태 전이를 모델링하고, 백그라운드 인지 프로세스를 실행하고, 벡터 인덱싱된 메모리를 유지할 수 있었습니다. Soul Spec은 그런 것을 할 수 없습니다.

하지만 OpenClaw이 사용하고 Soul Spec이 공식화한 선언적 패턴은, 런타임 엔진이 어려워하는 한 가지를 합니다: **플랫폼 변화를 살아남기**.

어디서든 동작하는 마크다운 파일이 하나의 스택에 묶인 정교한 엔진을 이깁니다.

## 빌더를 위한 시사점

AI 에이전트의 성격을 정의하는 방법을 선택한다면:

1. **독점 포맷을 피하라** — 플랫폼이 죽으면 당신의 작업도 죽는다
2. **데이터베이스보다 텍스트 파일을 선호하라** — 읽기 쉽고, 이식 가능하고, 버전 관리 가능
3. **페르소나와 런타임을 분리하라** — 에이전트의 성격이 프레임워크 선택에 의존해서는 안 된다
