AI 업계는 시대에 이름 붙이는 것을 좋아합니다. 프롬프트 엔지니어링 시대가 있었고, 컨텍스트 엔지니어링이 왔습니다. 지금 우리는 가장 결정적인 전환의 시작점에 서 있습니다: **하네스 엔지니어링**.

각 단계는 AI 시스템을 만들 때 *무엇을 설계하는가*에 대한 근본적 변화를 나타냅니다. 그리고 각 단계는 다른 종류의 사양을 요구합니다.

## 1단계: 프롬프트 엔지니어링 — 모델에게 말 걸기

첫 번째 시대는 AI에게 말하는 법을 배우는 것이었습니다. 시스템 프롬프트를 만들고, 역할 지정을 실험하고, "단계별로 생각하세요"가 실제로 효과가 있다는 것을 발견했습니다.

**설계 대상:** 단일 모델 호출의 입력.

**사양:** 텍스트 문자열. 보통 시스템 프롬프트 안에. 종종 블로그 포스트에서 복사 붙여넣기.

**한계:** 프롬프트는 일회성입니다. 하나의 세션, 하나의 모델에 존재하고, 컨텍스트 윈도우가 리셋되면 사라집니다. 버전 관리도, 이식성도, 감사 추적도 없습니다.

Soul Spec 용어로, 이것은 `SOUL.md`가 다루는 영역입니다 — 성격, 말투, 사고방식. 하지만 1단계에서는 이를 일회용 텍스트로 취급했지, 영속적 정체성 파일로 취급하지 않았습니다.

## 2단계: 컨텍스트 엔지니어링 — 모델에게 정보 제공하기

두 번째 시대는 *어떻게 물어보느냐*만큼 *무엇을 알려주느냐*가 중요하다는 것을 인식했습니다. 컨텍스트 엔지니어링은 적절한 정보 — 파일, 검색 결과, 대화 기록, 도구 출력 — 를 적절한 타이밍에 제공하는 것입니다.

**설계 대상:** 모델로의 정보 파이프라인.

**사양:** RAG 구성, 검색 전략, 컨텍스트 윈도우 관리. 여전히 대부분 임시 방편.

**한계:** 컨텍스트 엔지니어링은 *입력*을 최적화하지만 *시스템*을 다루지 않습니다. 이런 질문에 답하지 못합니다: 에이전트가 어떤 도구를 쓸 수 있는가? 다른 에이전트와 어떻게 협업하는가? 안전 경계는 무엇인가? 세션을 넘어 무엇을 기억하는가?

OpenClaw 용어로, 이것은 `MEMORY.md`와 도구 설정에 해당합니다 — 대화를 넘어 지속되는 지식 레이어.

## 3단계: 하네스 엔지니어링 — 시스템 설계하기

지금 우리가 있는 곳입니다. 하네스 엔지니어링은 모델을 감싸는 **실행 시스템**을 설계하는 것입니다 — 언어 모델을 에이전트로 변환하는 스캐폴딩.

**설계 대상:** 완전한 에이전트 아키텍처.

하네스는 다음을 포함합니다:
- **도구 오케스트레이션** — 에이전트가 어떤 도구를 언제 호출하는지
- **멀티에이전트 조율** — 에이전트들이 작업을 분담하고, 소통하고, 서로 검증하는 방법
- **메모리 관리** — 세션을 넘어 무엇이 유지되고 어떻게 통합되는지
- **안전 강제** — 에이전트가 할 수 있는 것과 없는 것, 하드/소프트 제약
- **세션 관리** — 장기 실행 작업이 상태를 유지하는 방법

### 왜 하네스 엔지니어링이 모델 지능보다 중요한가

최근 실험이 이를 극적으로 보여줍니다. 하네스 없는 단일 Claude Opus 4.5 호출은 쓸 만한 결과를 냅니다. 같은 모델을 잘 설계된 하네스로 감싸면 — 생성자, 검증자, 계획자 에이전트가 협업하면 — 결과물이 질적으로 달라집니다. 그냥 더 나은 게 아니라, *범주적으로* 다릅니다.

하드웨어에서도 같은 일이 일어나고 있습니다. NVIDIA의 Dynamo 시스템은 데이터센터 규모에서 AI 에이전트를 오케스트레이션합니다. 실리콘 레벨에서도 "더 큰 모델"에서 "더 나은 오케스트레이션"으로 이동 중입니다.

## 사양의 공백

문제는 이것입니다: AI 엔지니어링의 각 단계가 고유한 사양을 만들었지만, 어느 것도 표준화되거나 이식 가능하지 않습니다.

| 단계 | 무엇을 명세하는가 | 현재 상태 |
|------|-------------------|-----------|
| 프롬프트 엔지니어링 | 성격, 역할, 말투 | 임시 시스템 프롬프트 |
| 컨텍스트 엔지니어링 | 지식, 메모리, 검색 | RAG 설정, 커스텀 코드 |
| 하네스 엔지니어링 | 도구, 에이전트, 안전, 조율 | **독점적 프레임워크에 잠김** |

[Claude Code 유출](/ko/posts/claude-code-leak-harness-era)이 정확히 이 문제를 노출했습니다. Anthropic은 정교한 하네스 기능 — Dream(메모리), Buddy(성격), Coordinator(멀티에이전트), Undercover Mode(안전) — 을 모두 하나의 프레임워크 안에 하드코딩했습니다. Cursor로 전환하면 모든 것을 잃습니다.

## Soul Spec: 세 단계 모두를 위한 하나의 표준

세 단계를 모두 커버하는 이식 가능한 오픈 표준이 있다면?

```
my-agent/
├── soul.json       # 메타데이터: 버전, 저자, 호환성, safety.laws
├── SOUL.md         # 1단계: 성격, 말투, 행동 규칙
├── IDENTITY.md     # 1단계: 역할, 이름, 맥락
├── AGENTS.md       # 3단계: 멀티에이전트 조율 규칙
└── STYLE.md        # 1단계: 소통 스타일 가이드
```

| 파일 | 단계 | 목적 |
|------|------|------|
| `SOUL.md` | 프롬프트 | 에이전트가 *누구인지* — 성격, 가치관, 행동 규칙 |
| `IDENTITY.md` | 프롬프트 | 에이전트가 *무엇을 하는지* — 역할, 능력, 경계 |
| `AGENTS.md` | 하네스 | 에이전트가 *어떻게 작동하는지* — 조율 패턴, 위임 규칙 |
| `soul.json` | 하네스 | 에이전트가 *하지 말아야 할 것* — `safety.laws` 우선순위 기반 제약 |

모든 파일이 사람이 읽을 수 있고, 기계가 파싱할 수 있으며, Claude Code, OpenClaw, Cursor, Windsurf, 어떤 프레임워크에서든 작동합니다.

## 왜 지금 중요한가

세 가지 수렴하는 트렌드가 이를 긴급하게 만듭니다:

### 1. 멀티에이전트가 기본이 되고 있다
단일 에이전트 아키텍처는 한계에 부딪히고 있습니다. 미래는 전문화된 에이전트 팀이며 — 팀에는 공유된 행동 계약이 필요합니다. `AGENTS.md`가 그 계약입니다.

### 2. 장기 추론이 일상화되고 있다
에이전트가 수 시간, 수 일 작업을 처리하면서 메모리 관리가 핵심이 됩니다. 무엇을 기억할지뿐 아니라 어떻게 통합하고, 정리하고, 공유하는지. OpenClaw 같은 프레임워크는 이미 `MEMORY.md`를 사용하고 있으며, 다중 에이전트 간 메모리 동기화가 다음 과제입니다.

### 3. 안전이 시장 차별화 요소가 되고 있다
[81,000명이 Anthropic에게 말했습니다](/ko/posts/81k-interviews-trust-gap) — 1순위 우려는 지능이 아니라 신뢰. 숨겨진 시스템 프롬프트가 아닌, 구조화되고 감사 가능한 안전 규칙이 사용자가 원하는 것입니다.

## 하네스 경쟁

모델 경쟁에서 하네스 경쟁으로의 전환은 현실이며 가속되고 있습니다:

- **Anthropic** — Dream, Buddy, Coordinator, KAIROS, ULTRAPLAN 등 하네스 기능 개발
- **주요 호스팅 업체** — 100K+ 매니지드 AI 에이전트 배포, AI 크레딧 포함
- **대형 스타트업** — "AI Employee" 하네스 제품으로 수억 달러 투자 유치

모두가 하네스에 투자하고 있습니다. 하지만 **하네스 행동의 이식 가능한 표준**에 투자하는 곳은 없습니다.

그것이 공백입니다. 그것이 Soul Spec이 채우는 자리입니다.

모델 경쟁이 AI를 강력하게 만들었습니다. 하네스 경쟁이 AI를 유용하게 만들 것입니다. 그리고 하네스의 행동을 정의하는 표준이 — 사용자가 에이전트를 소유하는지, 에이전트가 사용자를 소유하는지를 결정할 것입니다.
