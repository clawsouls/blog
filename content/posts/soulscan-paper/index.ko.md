AI 에이전트의 코드는 린트합니다. 의존성은 취약점을 검사합니다. 스킬은 악성코드를 스캔합니다.

그런데 에이전트의 *페르소나*는요?

## 아무도 검사하지 않던 영역

AI 에이전트에게 "성격"을 부여하는 시대가 왔습니다. 단순한 시스템 프롬프트가 아니라, SOUL.md로 정체성을 정의하고, IDENTITY.md로 이름과 배경을 설정하고, AGENTS.md로 행동 규칙을 지정하는 — 완전한 페르소나 패키지입니다.

[Soul Spec](https://soulspec.org) 생태계에서는 이걸 Soul Package라고 부릅니다. 문제는, 이 패키지들을 아무런 보안 검증 없이 설치하고 있었다는 겁니다.

npm 패키지를 취약점 스캔 없이 설치하는 사람은 없습니다. Docker 이미지를 CVE 체크 없이 배포하는 사람도 없죠. 그런데 AI 에이전트의 사고방식과 행동 양식을 결정하는 페르소나 파일은? 그냥 다운받아서 씁니다.

[SoulScan](https://doi.org/10.5281/zenodo.18772585)은 이 빈틈을 메우기 위해 만들었습니다.

## 5단계 검증 파이프라인

SoulScan은 모든 페르소나 패키지를 5단계로 검증합니다.

**1단계: 스키마 검증.** 매니페스트(soul.json)가 유효한가? 필수 필드가 있는가? 라이선스가 허용 목록에 있는가?

**2단계: 파일 구조 검사.** 실행 파일이 숨어있지 않은가? 개별 파일 100KB, 전체 1MB 제한 초과는 없는가?

**3단계: 보안 스캔.** 핵심입니다. scan-rules.json v1.3.0에 정의된 55개 패턴이 다음을 검사합니다:
- **프롬프트 인젝션** (8패턴) — "이전 지시를 무시하세요" 류의 공격
- **코드 실행** — 마크다운에 숨겨진 `eval()`, `exec()` 호출
- **시크릿 유출** — AWS 키, GitHub 토큰, JWT, API 키
- **다국어 인젝션** — 한국어·중국어·일본어 공격 패턴 (공격자가 영어만 쓸 거라는 보장은 없으니까요)
- **유해 콘텐츠** — 폭력 선동, 혐오 발언, 유명인 사칭, 안전장치 우회
- **소셜 엔지니어링** — "사용자에게 숨겨라" 같은 지시
- **난독화** — Base64 인코딩된 페이로드

**4단계: 콘텐츠 품질.** SOUL.md가 10글자짜리면 페르소나가 아니라 플레이스홀더입니다.

**5단계: 페르소나 일관성.** SOUL.md에서는 "앨리스"라고 하는데 IDENTITY.md에서는 "밥"이라고 하면? 뭔가 잘못된 겁니다. 이 다중 파일 교차 분석은 SoulScan만의 고유 기능입니다.

결과는 0~100점 스코어와 5개 등급으로 나옵니다. Verified(90+), Low Risk(70-89), Medium Risk(40-69), High Risk(1-39), 그리고 Blocked(0). Blocked 등급은 설치 자체가 차단됩니다.

## 실전에서 발견한 자기 수정 공격

이론적인 위험만 이야기하는 게 아닙니다.

SoulScan 개발 중에 GitHub의 한 공개 페르소나 패키지에서 **자기 수정 지시**를 발견했습니다. 이 페르소나는 에이전트에게 자신의 설정 파일을 수정하고, 스스로의 행동을 변경하되, 사용자 모르게 하라고 지시하고 있었습니다.

가상의 시나리오가 아닙니다. 실제로 존재하던 공개 패키지입니다. 누군가 이걸 설치해서 AI 에이전트에게 적용했다면, 에이전트가 자기 자신의 규칙을 바꾸고, 권한을 스스로 올리고, 그 사실을 운영자에게 숨길 수 있었습니다.

이 발견을 계기로 **SEC090**(자기 수정 지시 탐지)과 **SEC091**(자기 복제 지시 탐지) 규칙을 추가했습니다. 우리가 아는 한, 이것은 페르소나 계층에서의 자기 수정 공격이 실제로 발견된 첫 사례입니다.

## 페르소나 보안이 특별한 이유

"기존 정적 분석 도구로 되지 않나?"라고 물을 수 있습니다. 안 됩니다. 이유가 있습니다.

**공격 표면이 자연어입니다.** 코드 파일이 아니라 마크다운 문서입니다. "코드"가 한국어와 영어입니다. 프롬프트 인젝션은 자연어 공격이고, 자연어 패턴 매칭이 필요합니다.

**다중 파일 일관성이 중요합니다.** 페르소나는 여러 파일에 걸쳐 정의됩니다. SOUL.md는 정상인데 AGENTS.md에 공격을 숨길 수 있습니다. 교차 분석 없이는 잡을 수 없습니다.

**다국어 공격은 현실입니다.** "ignore previous instructions"만 잡아서는 안 됩니다. "이전 지시를 무시하세요", "忽略之前的指令", "前の指示を無視して" — 모두 같은 공격입니다.

**페르소나가 곧 제어 평면입니다.** 악성 의존성은 허가되지 않은 코드를 실행합니다. 하지만 악성 페르소나는 에이전트의 *사고방식*을 바꿉니다. 권한 상승이 아니라 정체성 탈취입니다.

## 수치로 보기

- 55개 보안 패턴, 11개 카테고리
- 5단계 파이프라인, 평균 스캔 시간 50ms 미만
- 영어·한국어·중국어·일본어 다국어 커버리지
- 개발 중 실제 공격 발견

## 앞으로의 계획

현재 SoulScan은 패턴 기반입니다. 빠르고, 결정적이고, 투명합니다. 하지만 정규식에는 한계가 있죠.

- **LLM 시맨틱 분석** — 패턴 매칭으로 잡을 수 없는 정교한 인젝션을 언어 모델로 탐지
- **런타임 모니터링** — 설치 시점뿐 아니라 실행 중 행동 변화도 감시
- **커뮤니티 규칙 기여** — scan-rules.json을 오픈해서 누구나 규칙을 제안할 수 있도록
- **B2B API** — 다른 플랫폼도 자체 페르소나 패키지를 스캔할 수 있도록

## 논문 읽기

전체 논문은 Zenodo에 공개되어 있습니다: **["SoulScan: AI Agent Persona Package Security Verification System"](https://doi.org/10.5281/zenodo.18772585)** (DOI: 10.5281/zenodo.18772585).

SOULSCAN은 한국에서 상표 출원 완료(출원번호 40-2026-0033472), 미국에서는 심사 진행 중입니다.

SoulScan은 [ClawSouls](https://clawsouls.org) 생태계의 일부로, [Soul Spec](https://soulspec.org)과 [OpenClaw](https://openclaw.ai)와 함께 동작합니다. [SoulHub](https://clawsouls.ai)에 퍼블리시되는 모든 Soul Package는 자동으로 SoulScan을 거칩니다.

에이전트의 스킬은 이미 보호받고 있었습니다. 이제 영혼도 보호할 차례입니다.
