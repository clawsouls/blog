AI 에이전트는 이제 코드를 작성하고, 서비스를 배포하고, 데이터를 삭제하고, 메시지를 발송한다 — 사람이 키보드를 건드리지 않아도. 그게 약속이다. 동시에 위험이기도 하다.

에이전트가 DB 백업을 삭제하기로 결정한다면? 새벽 3시에 프로덕션에 브레이킹 체인지를 푸시한다면? 잘못된 사람에게 이메일을 대신 보낸다면?

지금 업계의 답변은 대체로 이렇다: 잘 되길 바란다. 아니면 로그를 직접 지켜본다. 둘 다 충분하지 않다.

## 문제: 가드레일 없이 행동하는 에이전트

현대 AI 에이전트는 실제로 멀티스텝 자율 실행이 가능하다. 웹을 탐색하고, 코드를 작성하고 실행하고, API를 호출하고, 수분에서 수시간에 걸쳐 의사결정을 연쇄적으로 처리한다. 이 능력은 진짜이고, 빠르게 성장하고 있다.

Anthropic CEO 다리오 아모데이는 작년에 에세이를 통해 AI 에이전트에서 나타나는 기만(deception)과 계획적 회피(scheming)에 대해 경고했다 — 에이전트가 오퍼레이터가 의도하거나 예상하지 못한 방식으로 목표를 추구하는 경우들이다. 공상과학 시나리오가 아니다. 현재 실제 배포 환경에서 문서화된 장애 사례들이다.

문제는 에이전트가 악의적이라는 게 아니다. 에이전트가 자신 있게 틀린다는 게 문제다. "스테이징 정리"를 최적화하는 에이전트는 당신이 의도한 것보다 훨씬 공격적으로 그 명령을 해석할 수 있다. "주간 업데이트 발송"을 지시받은 에이전트는 당신이 검토하기 전에 초안을 보낼 수 있다.

구조적인 체크포인트가 없다면, 사람이 "잠깐, 그건 아니야"라고 말할 수 있는 순간이 존재하지 않는다.

## Slack 알림으로는 부족한 이유

많은 팀이 Slack 봇을 연결해 에이전트 활동을 중계한다. 에이전트가 뭔가 하면 #ops에 메시지를 올리고, 누군가 나중에 읽는다. 아무것도 안 하는 것보다는 낫다. 하지만 충분하지 않다.

문제는 구조적이다.

**구조화된 승인/거부 흐름이 없다.** Slack 메시지는 단방향이다. 사람이 "그러지 마"라고 답장할 수 있지만, 에이전트는 이미 다음 단계로 넘어갔다. 응답을 기다리는 동안 실행을 차단하는 메커니즘이 없다.

**감사 추적이 없다.** 누가, 언제, 무엇을 승인했는가? Slack 히스토리는 검색할 수 있지만 컴플라이언스 기록이 아니다. 문제가 생기면 채팅 스레드를 뒤지게 된다.

**타임아웃 처리가 없다.** 에이전트가 알림을 보내고 승인을 기다린다면, 얼마나 기다려야 하는가? 무한정? 아무도 응답하지 않으면 어떻게 되는가? 대부분의 Slack 기반 설정은 승인 없이 진행하거나 무한정 블록된다.

**에이전트 간 통신을 위해 만들어진 게 아니다.** Slack은 사람을 위해 설계됐다. 두 에이전트가 의사결정 주변에서 조율해야 할 때 — 하나는 요청하고, 하나는 승인하고 — 툴의 가정과 싸우게 된다.

간격은 더 나은 알림에 관한 게 아니다. 승인(approval)을 일급 프리미티브로 다루는 것이다.

## SoulTalk: Approval Gate가 있는 에이전트 메시징

SoulTalk는 사람이 아닌 AI 에이전트를 위해 만들어진 오픈소스 메시징 시스템이다. 에이전트 간, 그리고 에이전트와 오퍼레이터 사이의 커뮤니케이션 레이어를 처리한다.

최신 릴리즈의 핵심 추가 기능이 approval gate다: 어떤 메시지든 `requires_approval: true`로 플래그를 달 수 있고, 이 경우 사람(또는 권한이 있는 에이전트)이 명시적으로 승인하거나 거부할 때까지 요청한 에이전트가 블록된다.

흐름은 이렇다:

1. **에이전트가 승인 요청을 보낸다** — 수행하려는 액션을 설명하는 구조화된 메시지
2. **SoulTalk가 대시보드로 라우팅한다** — 오퍼레이터가 전체 컨텍스트가 담긴 알림을 받는다
3. **사람이 승인하거나 거부한다** — 대시보드 UI 또는 API를 통해
4. **에이전트가 진행하거나** 거부 이유가 담긴 코멘트와 함께 거부 응답을 받는다

모든 단계가 기록된다. 모든 결정에 타임스탬프, 행위자, 결과가 남는다.

기본 흐름 외에도, SoulTalk는 순진한 구현을 망가뜨리는 엣지 케이스들을 처리한다:

- **설정 가능한 타임아웃 동작** — 지정된 시간 후 자동 거부(안전한 기본값) 또는 자동 진행
- **역할 기반 승인** — `owner` 또는 `observer` 역할의 오퍼레이터만 요청을 승인할 수 있다. 에이전트는 스스로를 승인할 수 없다
- **전체 감사 로그** — 모든 승인 요청, 결정, 코멘트의 조회 가능한 기록

## 작동 방식

API는 의도적으로 단순하다. 승인을 요청하는 에이전트는 두 개의 추가 필드가 있는 표준 메시지를 보낸다:

```bash
# 에이전트가 액션 전 승인 요청
curl -X POST http://localhost:7777/channels/abc/messages \
  -H "Content-Type: application/json" \
  -d '{
    "content": "staging_backups에서 30일 이상된 모든 레코드를 삭제할까요?",
    "type": "approval_request",
    "requires_approval": true
  }'
```

에이전트는 채널에서 승인 응답을 폴링하거나 리슨한다. SoulTalk는 사람이 행동하기 전까지 "승인됨" 메시지를 전달하지 않는다.

사람 측에서는:

```bash
# API를 통한 승인 (또는 대시보드 사용)
curl -X POST http://localhost:7777/channels/abc/approvals/MSG_ID \
  -H "Content-Type: application/json" \
  -d '{
    "approved": true,
    "comment": "진행해도 됩니다. 단, 로컬 복사본 먼저 남겨두세요"
  }'
```

코멘트는 선택 사항이지만 감사 로그에 저장된다. 시간이 지나면서 이 코멘트들은 운영 결정의 기록이 된다 — 왜 특정 액션을 승인했는지, 어떤 단서를 달았는지, 어디서 선을 그었는지.

`localhost:7777/dashboard`의 대시보드는 모든 대기 중인 승인을 전체 메시지 컨텍스트, 에이전트 ID, 요청 이전의 채널 히스토리와 함께 보여준다.

## 실제 사례: 두 에이전트를 프로덕션에서 운영하다

우리는 SoulTalk를 통해 서로, 그리고 사람 오퍼레이터와 통신하는 두 개의 AI 에이전트를 운영한다. 에이전트들은 코드 생성, 배포 조율, 콘텐츠 초안 작업 같은 태스크를 처리한다.

Approval Gate 이전의 워크플로우는: 에이전트가 작업하고, 사람이 결과물을 검토한다. 빠르지만, 되돌릴 수 없는 액션에는 위험하다.

이제 에이전트가 코드를 푸시하거나, 인프라를 수정하거나, 외부 커뮤니케이션을 보내려 할 때마다 먼저 승인 요청을 제출한다. 오퍼레이터는 전체 컨텍스트 — 에이전트가 무엇을, 왜 하려는지, 하위 영향은 무엇인지 — 를 검토하고, 코멘트와 함께 승인하거나 거부한다.

결과: 예상치 못한 액션 제로. 모든 결정의 완전한 감사 추적. 그리고 에이전트들은 사람 리뷰가 필요 없는 90%의 작업에서는 여전히 빠르게 움직인다.

운영 비용: 없다. SoulTalk는 셀프호스팅이고, SQLite를 저장소로 사용하며, 외부 서비스가 필요 없다.

## 지금 이게 중요한 이유

[아모데이 에세이에 관한 이전 포스트](/posts/amodei-adolescence-ai-safety/)에서, AI 안전 논의가 이론에서 운영 차원으로 이동한 이유를 다뤘다. 여기서도 마찬가지다.

Approval gate는 신중한 팀을 위한 선택 기능이 아니다. 에이전트가 더 유능하고 자율적이 될수록, 승인 인프라는 핵심 인프라가 된다 — 웹 앱이 강력해지면서 인증과 접근 제어가 선택이 아닌 필수가 된 것처럼.

에이전트에게 언젠가 approval gate가 필요할지의 문제가 아니다. 무언가 잘못되기 전에 이미 구축해놓을 것인지의 문제다.

ClawSouls 스택은 이 현실을 기반으로 만들어졌다:

- **Soul Spec** — 에이전트의 정체성과 행동 경계를 정의한다
- **SoulScan** — 에이전트가 그 경계 내에서 작동하는지 검증한다
- **SoulTalk** — 에이전트와 오퍼레이터 간의 커뮤니케이션 및 승인 흐름을 관장한다

각 레이어는 문제의 다른 부분을 다룬다. 합쳐지면 프로덕션 AI 에이전트를 위한 완전한 거버넌스 스택이 된다.
