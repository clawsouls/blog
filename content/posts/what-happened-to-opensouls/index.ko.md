## 부상

OpenSouls(GitHub ⭐294)는 스스로를 "디지털 존재의 마음을 위한 NextJS + Vercel"로 포지셔닝했습니다. 인상적인 런타임 엔진을 만들었습니다:

- **WorkingMemory**: 불변 메모리 컬렉션
- **cognitiveSteps**: 메모리를 변환하고 타입된 응답을 반환하는 함수
- **MentalProcesses**: 행동 모드를 위한 상태 머신 (소개 → 추측 → 좌절)

신경과학과 심리학에서 영감을 받았습니다. `@opensouls/soul` npm 패키지는 76개 버전까지 출시되었습니다.

## 왜 죽었는가

확실히 알 수는 없지만, 증거는 몇 가지 요인을 가리킵니다:

### 1. 런타임 종속
Bun 전용, TypeScript 전용. OpenSouls를 사용하려면 그들의 전체 스택에 종속되어야 했습니다. LLM 생태계가 엄청난 속도로 진화하는 상황에서 하나의 런타임에 종속되는 것은 부담이 되었습니다.

### 2. 복잡성 vs 가치
WorkingMemory, cognitiveSteps, MentalProcesses... 가파른 학습 곡선. 한편 대부분의 개발자는 잘 작성된 시스템 프롬프트로 80%까지 도달할 수 있다는 것을 알았습니다. 나머지 20%는 완전히 새로운 프레임워크를 배울 가치가 없었습니다.

### 3. 시장 전환
"AI 캐릭터" 붐(Character.AI 시대)에 시작했습니다. 시장은 빠르게 **에이전트와 도구 사용**으로 전환했습니다. 감정/성격 엔진이 갑자기 덜 중요해졌습니다.

### 4. 비즈니스 모델 공백
오픈소스 엔진 + 클라우드 호스팅. 하지만 개발자들은 LLM API를 직접 호출하면 됐습니다. 왜 미들웨어 레이어를 추가하는가?

## 우리에게 주는 교훈

Soul Spec은 근본적으로 다른 접근을 취합니다. OpenClaw 같은 프레임워크가 이미 확립한 선언적 파일 패턴을 기반으로 합니다:

| | OpenSouls | ClawSouls |
|---|---|---|
| 접근 방식 | 런타임 엔진 (Node.js) | 선언적 스펙 (텍스트 파일) |
| 종속성 | Bun + TypeScript 필수 | 프레임워크 비종속 |
| 학습 곡선 | 높음 (커스텀 SDK) | 낮음 (마크다운 파일) |
| 보안 | 없음 | SoulScan™ 자동 검증 |
| 상태 | 서비스 종료 | 활성, 80+ 소울 |

**핵심 통찰**: 페르소나는 **코드가 아니라 데이터**여야 합니다. 어떤 프레임워크든 읽을 수 있는 텍스트 파일이지, 종속을 만드는 SDK가 아닙니다. OpenClaw 같은 프레임워크가 이미 이것을 이해하고 있었고 — Soul Spec은 이를 이식 가능하고 검증 가능한 표준으로 공식화합니다.

OpenSouls는 수요가 존재한다는 것을 증명했습니다. 다만 잘못된 추상화 레이어를 선택했을 뿐입니다.
