최근 *"나는 바이브코딩을 그만뒀다 (I Stopped Vibecoding)"*라는 글이 큰 반향을 일으켰다. 글쓴이는 2년간 AI 코딩 도구를 점점 더 깊이 활용했다 — 작은 작업부터 시작해 결국 전체 기능을 맡겼다. 흥분은 다음을 깨달으며 식었다:

- AI가 세션 간 **장기적 맥락을 유지하지 못함**
- 상세한 명세서를 작성해도 AI는 이를 살아있는 문서가 아닌 정적 문서로 취급
- 코드가 함수 단위로는 괜찮아 보이지만 시스템 차원에서는 **구조적 일관성이 없음**
- 글쓴이 자신도 코드베이스의 멘탈 모델을 잃어버림

이건 실력 문제가 아니다. 아키텍처 문제다.

## 근본 원인: Stateless 에이전트

모든 주류 AI 코딩 도구 — Copilot, Cursor, Claude Code — 는 매 세션을 백지에서 시작한다. 에이전트는 어제 무엇을 결정했는지 기억하지 못한다. 인증 모듈을 *왜* 그렇게 구조화했는지 모른다. 새로운 유틸리티 함수가 세 세션 전에 확립한 패턴과 모순된다는 것을 알 수 없다.

결과? **아키텍처 드리프트.** 각 세션은 지역적으로 올바르지만 전역적으로 맞지 않는 코드를 생산한다. 글쓴이는 이를 "순수한 난잡함(pure slop)"이라 불렀다. 실제로는 기억을 잃은 건축가의 자연스러운 결과물이다.

## 세 가지 빠진 조각

바이브코딩 문제는 세 가지 갭으로 분해된다:

### 1. 장기 기억

에이전트는 과거의 결정, 패턴, 근거를 기억해야 한다 — 현재 파일만이 아니라. 기억이 없으면 매 세션이 컨텍스트 제로에서 시작된다.

**실제로 어떤 모습인가:** 과거 대화와 결정에 대한 시맨틱 검색. *"여기서 PostgreSQL 대신 Redis를 쓴 이유가 뭐였지?"* — 에이전트가 당신이 남겨놓길 바라는 주석이 아니라, 자신의 기억에서 답할 수 있어야 한다.

### 2. 정체성 지속 (페르소나 드리프트)

AI에게 시스템 프롬프트를 주면 작동한다... 그 세션 동안만. 다음 세션에서 에이전트는 미묘하게 다른 컨벤션, 네이밍 패턴, 아키텍처 선호를 채택할 수 있다. 시간이 지나면 코드베이스는 미세하게 다른 50명의 "개발자"가 작업한 결과물을 반영한다.

**실제로 어떤 모습인가:** 선언적 파일 — 우리는 이를 `SOUL.md`라 부른다 — 이 에이전트의 원칙, 코딩 스타일, 제약 조건을 정의한다. 버전 관리되고, diff 가능하고, 롤백 가능하다. 세션 사이에 사라지는 숨겨진 시스템 프롬프트가 아니다.

### 3. 살아있는 명세

이 글이 정확히 짚었다: 실제 개발 명세는 발견 과정에서 진화한다. 워터폴 방식의 "명세를 쓰고, 그다음 생성"은 작동하지 않는다. 왜냐하면 만드는 것 자체가 이해하는 것이기 때문이다. 에이전트는 프로젝트가 진화함에 따라 자신의 멘탈 모델을 업데이트해야 한다.

**실제로 어떤 모습인가:** 머신 간 동기화되는 메모리, 에이전트 상태를 스냅샷하고 롤백할 수 있는 체크포인트, 에이전트의 행동이 정의된 원칙에서 벗어날 때 잡아내는 보안 스캐닝.

## 우리의 접근 (솔직한 현황: 진행 중)

우리는 [SoulClaw](https://soulclaw.sh)를 만들고 있다 — 이 세 가지 갭을 해결하는 오픈소스 AI 에이전트 프레임워크:

- **SOUL.md** — 에이전트의 성격, 원칙, 코딩 스타일을 정의하는 마크다운 파일. 레포에 체크인된다. 세션을 넘어 유지된다. 현재 [89개 이상의 커뮤니티 Soul](https://clawsouls.ai) 사용 가능.

- **Swarm Memory** — 머신 간 Git 기반 메모리 동기화. 회사 맥과 집 데스크탑의 에이전트가 같은 기억을 공유한다. Age 암호화, LLM 기반 머지 충돌 해결.

- **SoulScan** — 55개 이상의 보안 룰로 프롬프트 인젝션, 권한 상승, 정체성 드리프트를 탐지. 커뮤니티 페르소나를 다운로드할 때 안전한지 알 수 있어야 하니까.

- **Soul Checkpoint** — 에이전트 설정을 스냅샷하고 롤백. 다른 페르소나를 실험하면서도 작동하는 설정을 잃지 않는다.

**완성됐나?** 아직 아니다. UX에 거친 부분이 있다. 일부 기능은 초기 단계다. 하지만 방향은 명확하다: **AI 에이전트는 상태를 가지고, 지속적이며, 버전 관리되어야 한다** — 그들이 작성하는 코드처럼.

## 더 큰 그림

바이브코딩 글은 인간이 직접 코딩으로 돌아가야 한다고 결론짓는다. 우리는 중간 지점이 있다고 생각한다: AI 에이전트를 시간이 지남에 따라 지식을 축적하고, 일관된 원칙을 유지하며, 버전 관리를 통해 책임을 질 수 있는 *진짜 협업자*로 만드는 것.

문제는 AI가 나쁜 코드를 쓰는 것이 아니다. AI가 세션 사이에 모든 것을 잊고 일관된 정체성이 없다는 것이다. 이를 고치면, 바이브코딩은 실제로 작동할 수 있다.
